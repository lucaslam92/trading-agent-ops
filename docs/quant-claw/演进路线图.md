# Quant Claw 演进路线图

## 1. 文档目的

本文档用于描述 `quant-claw` 从当前 MVP 形态，逐步演进到更强工程化和更接近生产可用状态的路线。

## 2. 当前状态

当前系统已具备：

- 多 Agent 分工结构
- 事件驱动主链路
- 资金费率示例策略
- 风控审批
- paper broker 执行
- 持仓更新
- API 查询入口
- simulation 测试样例

这说明项目已经不是纯概念，而是具备了最小可运行闭环。

## 3. 演进阶段

### 阶段一：MVP 闭环稳定

目标：把现有链路跑稳，而不是继续无序扩功能。

重点：
- 冻结核心 topic
- 冻结核心 schema
- 提高 simulation 测试覆盖率
- 明确 strategy / risk / execution 三层职责

交付物：
- 稳定的 demo flow
- 核心文档齐备
- 本地可复现启动方式

### 阶段二：工程能力增强

目标：从“能跑”升级到“可维护”。

重点：
- Redis 事件总线标准化
- Postgres 持久化模型增强
- 日志、指标、审计补齐
- 幂等与重放能力设计
- 错误处理与状态机补齐

交付物：
- 更完整的运维可观测性
- 更可追踪的事件生命周期
- 更稳的服务边界

### 阶段三：策略与环境扩展

目标：从单条 demo 路径扩展到多策略、多团队、多环境。

重点：
- 多 strategy 配置
- team 级编排能力
- backtest / sim / paper 隔离
- 市场数据适配层抽象
- 风控规则模块化

交付物：
- 可配置多策略系统
- 更清晰的研发 / 测试 / 运行环境边界
- 可持续扩展的配置体系

### 阶段四：走向实盘准备

目标：从工程样板走向真实交易系统准备期。

重点：
- 实盘 broker / exchange adapter
- 更严格的风控与熔断
- 人工审批与 kill switch
- 运维 runbook
- 权限、审计、合规流程

交付物：
- 接近生产的系统边界设计
- 实盘安全控制框架
- 面向上线前的治理体系

## 4. 环境路线

### Backtest

定位：历史验证、策略研究

要求：
- 历史数据回放
- 可重复运行
- 结果可比较

### Simulation

定位：集成验证、主链路联调

要求：
- mock / replay 事件
- paper broker
- 快速反馈

### Paper Trading

定位：接近真实市场但不动真资金

要求：
- 接真实行情
- 保留大部分运行时控制
- 风控与监控接近实盘

### Live Trading

定位：真实交易执行

要求：
- 真实交易所连接
- 更强风控
- 完整审计
- 应急预案

## 5. 关键建设优先级

建议优先级从高到低如下：

1. Schema / Topic 治理
2. 测试与回放机制
3. Risk 模块化
4. Execution 适配器抽象
5. Market Data 契约标准化
6. 监控、审计与告警
7. 多策略、多团队能力

## 6. 不建议过早做的事

在 MVP 尚未稳定前，不建议过早投入：

- 花哨 UI
- 复杂权限系统
- 过度抽象的插件体系
- 多交易所全覆盖
- 高度复杂的组合优化层

这些东西并非不重要，而是不该抢在核心闭环稳定之前。

## 7. 路线图结论

这套系统最合理的推进方式不是“直接冲实盘”，而是：

**先把 sim 闭环做稳，再做工程化，再扩策略和环境，最后再碰 live。**

这样能显著降低系统复杂度失控和风险外溢的概率。
